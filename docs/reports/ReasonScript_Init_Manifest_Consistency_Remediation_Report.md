# ReasonScript Init & Manifest Consistency Remediation Report
# reason init および Manifest 契約整合性修正完了レポート

## 1. Completion Summary / 完了概要

- **Task / タスク**: GitHub Issue #31 (`[Epic] reason init と Manifest 契約の整合性を修正する`), #32, #33, #34, #35, #36
- **Status / ステータス**: COMPLETED / 完了
- **Version / バージョン**: ReasonScript 0.5.5.9 / Install Foundation 1.1

### English
This work resolves the manifest inconsistency where projects generated by `reason init` triggered `UserWarning: Unknown sections in reason.toml: artifacts, project, source` during `reason build`. The canonical `Manifest` model now officially supports and validates all standard sections (`package`, `project`, `source`, `artifacts`, `compiler`, `runtime`, `dependencies`, `capabilities`), enforces deterministic diagnostic warnings for unknown keys and sections, rejects directory traversal / path escapes, and integrates `source.entry` and `artifacts.directory` consistently across `build`, `check`, `run`, and `artifacts` commands.

### 日本語
本改修では、`reason init` で生成された標準プロジェクトを `reason build` した際に `UserWarning: Unknown sections in reason.toml: artifacts, project, source` が発生する契約不整合を解消しました。正規の `Manifest` データモデルにおいて、標準の6セクションおよび拡張セクション（`package`, `project`, `source`, `artifacts`, `compiler`, `runtime`, `dependencies`, `capabilities`）を正式に認識・解析・バリデーションするように拡張しました。また、未知セクション・未知キーの警告順序を決定的に整流化し、ルート逸脱パスの拒否、`source.entry` / `artifacts.directory` の CLI ビルド・実行・成果物経路への一貫した反映を完了しました。

## 2. Implemented Features / 実装項目

### English
1. **Canonical Manifest Model Extension (`toolchain/manifest.py`)**:
   - Added `project`, `source`, and `artifacts` to `KNOWN_SECTIONS`.
   - Defined `KNOWN_SECTION_KEYS` and deterministic warning emissions for unknown sections and keys.
   - Added fields `identifier`, `project_name`, `project_version`, `reason_version`, `source_entry`, `artifacts_directory`, and `capabilities` to the `Manifest` dataclass.
   - Implemented strict path validation: `source.entry` and `artifacts.directory` cannot be absolute paths or escape the project root via `..`.
   - Maintained complete backward compatibility with legacy manifests lacking `project`, `source`, or `artifacts` sections by providing default values.
2. **CLI Build & Check Integration (`toolchain/build_cmd.py`, `toolchain/check_cmd.py`, `toolchain/run_cmd.py`)**:
   - `build` and `check` now validate that `manifest.source_entry` exists and include it as the canonical entry point in source collections.
   - `run` respects `manifest.source_entry` during source discovery.
3. **Artifact Output Unification (`scripts/reason_cli.py`)**:
   - Replaced ad-hoc `tomllib.loads` in `_artifact_output` with canonical `Manifest.load(project_root)`.
4. **Automated Regression Test Suite (`tests/cli/test_manifest_consistency.py`, `toolchain_phase1_tests/test_toolchain_conformance.py`)**:
   - End-to-end testing of `reason init` -> `reason build` -> `reason run` with zero warnings.
   - Verifies warnings for unknown sections and unknown keys.
   - Verifies rejection of root escapes (`../outside`).
   - Verifies custom `source.entry` and custom `artifacts.directory`.
   - Verifies deterministic diagnostic output across multiple runs.
5. **CLI Reference Documentation (`docs/reference/ReasonScript_v0_5_CLI_Reference.md`)**:
   - Documented the full standard `reason.toml` section structure, diagnostic policy, and `reason init` layout.

### 日本語
1. **正規 Manifest モデルの拡張 (`toolchain/manifest.py`)**:
   - `KNOWN_SECTIONS` に `project`, `source`, `artifacts` を追加。
   - `KNOWN_SECTION_KEYS` を定義し、未知セクションおよび既知セクション内の未知キーに対する警告をアルファベット順（決定的）に出力。
   - `Manifest` クラスに `identifier`, `project_name`, `project_version`, `reason_version`, `source_entry`, `artifacts_directory`, `capabilities` を追加。
   - 厳格なパス検証: `source.entry` および `artifacts.directory` の絶対パス指定、および `..` 等によるプロジェクトルート逸脱を禁止。
   - `project`, `source`, `artifacts` が存在しない旧形式のマニフェストに対しても、既存デフォルトを適用することで完全な後方互換性を維持。
2. **CLI ビルド・チェック経路への反映 (`toolchain/build_cmd.py`, `toolchain/check_cmd.py`, `toolchain/run_cmd.py`)**:
   - `build` および `check` において `manifest.source_entry` の存在確認を実施し、ソース収集の正規エントリとして統合。
   - `run` においても `manifest.source_entry` を考慮したソース探索を実施。
3. **成果物出力処理の正規化 (`scripts/reason_cli.py`)**:
   - `_artifact_output` での独自の `tomllib.loads` を廃止し、正規の `Manifest.load(project_root)` へ集約。
4. **自動回帰テストの追加 (`tests/cli/test_manifest_consistency.py`, `toolchain_phase1_tests/test_toolchain_conformance.py`)**:
   - `reason init` -> `reason build` -> `reason run` が警告ゼロで成功することの E2E 検証。
   - 未知セクションおよび未知キーの警告検出検証。
   - ルート逸脱パス (`../outside`) の拒否検証。
   - カスタム `source.entry` およびカスタム `artifacts.directory` の反映検証。
   - 複数回実行時の診断出力の決定性検証。
5. **CLI リファレンス文書の整備 (`docs/reference/ReasonScript_v0_5_CLI_Reference.md`)**:
   - 標準 `reason.toml` のセクション・キー構成、診断方針、および `reason init` の生成仕様を明文化。
