# Syntax

Audience: developers writing ReasonScript. This page covers the current
Language Surface — modules, functions, structs, enums, pattern matching,
and Calculations. Source files use the `.rsn` extension.

For the underlying execution model these constructs compile down to, see
[semantics.md](semantics.md) and
[docs/architecture/compiler.md](../architecture/compiler.md). For type
annotations specifically, see [type-system.md](type-system.md).

## Modules

Every compilation unit has exactly one `module` as its root:

```reasonscript
module Basic {
    fn Value() -> int {
        return 42
    }
}
```

A package-level file (as generated by `reason init`) also declares a
`package` name above the module:

```reasonscript
package hello_world
module main {
    fn run(goal) {
        return goal
    }
}
```

Canonical module names match `[A-Za-z_][A-Za-z0-9_]*(\.[A-Za-z_][A-Za-z0-9_]*)*`.
Nested modules are not supported — exactly one `Module` per compilation
unit. See
[ReasonScript_Language_Specification_v0.1.md](../specifications/ReasonScript_Language_Specification_v0.1.md).

## Imports

```reasonscript
import User
import tools.weather
```

Imports use the exact canonical module name only — no wildcards, aliases,
relative imports, or selective imports. Duplicate and cyclic imports
(including self-imports) are compile-time errors. Imported symbols must
always be used fully qualified; there is no unqualified injection into the
importing module's namespace.

## Functions

```reasonscript
module Basic {
    fn Value() -> int {
        return 42
    }
}
```

Parameters take a type annotation; see [type-system.md](type-system.md).

## Calculations

A `calculation` block computes a named result, typically by calling a
function:

```reasonscript
module Basic {
    fn Value() -> int {
        return 42
    }

    calculation Result {
        result = Value()
    }
}
```

See
[ReasonScript_Language_Surface_Calculation_Integration_v0.1.md](../specifications/ReasonScript_Language_Surface_Calculation_Integration_v0.1.md).

## Enums

```reasonscript
module Basic {
    enum Color {
        Red
        Blue
    }

    fn Get() -> Color {
        return Color.Red
    }
}
```

Enum variants are always referenced qualified (`Color.Red`), never bare.

## Pattern Matching

`match` supports enum variants, struct destructuring, field bindings,
guards, or-patterns, and a `default` catch-all arm.

```reasonscript
fn Score(value: int) -> int {
    match value {
        1 | 2 | 3 => return 10
        default => return 0
    }
}
```

```reasonscript
fn Score(color: Color) -> int {
    match color {
        Color.Red => return 1
        Color.Blue => return 2
    }
}
```

Struct patterns support literal fields, field bindings, mixed forms, and an
empty `Point { }` catch-all:

```reasonscript
fn Score(point: Point) -> int {
    match point {
        Point { x: 0 } | Point { y: 0 } => return 10
        Point { } => return 0
    }
}
```

Guards (`when <bool-expression>`) run after the pattern binds, and a
guarded arm does **not** count toward exhaustiveness — you still need an
unguarded fallback:

```reasonscript
fn Score(point: Point) -> int {
    match point {
        Point { x } when x > 0 => return 1
        Point { } => return 0
    }
}
```

Each of these forms has a normative spec under `docs/specifications/`:
[or_pattern_v1.md](../specifications/or_pattern_v1.md),
[struct_pattern_matching_v1.md](../specifications/struct_pattern_matching_v1.md),
[pattern_guard_v1.md](../specifications/pattern_guard_v1.md),
[struct_exhaustiveness_v1.md](../specifications/struct_exhaustiveness_v1.md),
[default_exhaustiveness_integration_v1.md](../specifications/default_exhaustiveness_integration_v1.md),

## Legacy Core Grammar (Historical)

Before the current Language Surface existed, an earlier, much smaller
line-based grammar was used directly by the runtime prototype — six
single-line statement keywords (`goal`, `derive`, `prove`, `apply`,
`compute`, `converge`, `rollback`), one statement per line, no blocks or
imports:

```text
goal scalar_math
compute 1/2 + 3/4
converge verify_numeric_result
```

```text
goal preserve_session_consistency
apply patch_session_machine
prove invalid_transition
converge verify_repl_stability
```

This grammar still exists and is documented normatively in
[grammar.md](../specifications/grammar.md) and
[semantics.md](../specifications/semantics.md) — some conformance fixtures
under `examples/` still use it — but it is not what you should write new
`.rsn` programs in. Use the module/function surface above.
