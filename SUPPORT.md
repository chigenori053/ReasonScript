# Support

This document explains where to get help with ReasonScript.

## Documentation

Start with the three documentation layers described in the
[README](README.md#9-documentation):

- [Guides](docs/guides/) — installation, quick start, first project
- [Language reference](docs/language/) and [CLI/diagnostics reference](docs/references/)
- [Architecture](docs/architecture/) and [Specifications](docs/specifications/)
  for implementation-level detail

The [glossary](docs/references/glossary.md) is the fastest way to resolve an
unfamiliar term (`ReasonUnit`, `SemanticPlan`, `WorldModel`, and so on).

## Asking a question

1. Search existing [GitHub Issues](https://github.com/chigenori053/reasonscript/issues)
   and [Discussions](https://github.com/chigenori053/reasonscript/discussions)
   (if enabled for the repository) for the same question.
2. If nothing matches, open a new Discussion (preferred for "how do I..."
   questions) or an Issue tagged `question`.
3. Include: what you were trying to do, the exact command or code, the full
   error output, your ReasonScript version (`reason --version` or the
   [`VERSION`](VERSION) file contents), and your OS/toolchain versions
   (`rustc --version`, `python3 --version`).

## Reporting a bug

Use a GitHub Issue with the `bug` label. See
[CONTRIBUTING.md](CONTRIBUTING.md#reporting-bugs) for what to include.

## Reporting a security issue

Do **not** open a public issue. Follow the process in
[SECURITY.md](SECURITY.md).

## Contributing fixes or features

See [CONTRIBUTING.md](CONTRIBUTING.md).

## Response times

ReasonScript is maintained by volunteers on a best-effort basis. There is no
guaranteed response time. See [GOVERNANCE.md](GOVERNANCE.md) for how
maintainer decisions are made.
